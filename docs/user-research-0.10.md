# 0.10：空间告急的使用路径与研究记录

记录日期：2026-09-27。本轮依据公开用户求助、官方资料与源码检查归纳需求；没有开展真实用户访谈，不推断需求比例。人工可用性仍待验证。

## 证据与产品判断

| 观察 | 来源与局限 | 本轮落实 |
| --- | --- | --- |
| 找到大文件仍不敢动，少量缓存清理不能解决困境 | [WindowsHelp 求助](https://www.reddit.com/r/WindowsHelp/comments/1tx82gs/windows_11_c_drive_keeps_filling_up_on_its_own/)，个例自述，不验证其磁盘故障原因 | 磁盘入口、逐层只读定位、直接展示用途与操作 |
| 清出空间后很快又满 | [WindowsHelp 求助](https://www.reddit.com/r/WindowsHelp/comments/1tsc756/what_is_happening_with_my_storage/)，不能归因为某一程序 | 显示同卷观察变化，允许负增长，不把删除量当作持续收益 |
| 清理应逐步处理并检查是否足够 | [微软空间释放说明](https://support.microsoft.com/en-us/windows/experience/storage-filemanagement/free-up-drive-space-in-windows) | 当前盘采样、刷新、用户主动重新分析；不强制填写目标 GB |
| 应用内有缓存、备份与存储管理入口，版本间存在差异 | [WPS 官方说明](https://bbs.wps.cn/topic/93227) | 标注已核实版本菜单；未核实版本使用应用内查找方法，不伪造跳转 |
| 可用字节受当前用户配额影响 | [GetDiskFreeSpaceExW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getdiskfreespaceexw) | 沿用调用者可用字节，不补造物理总量、不推算隐藏垃圾 |

从普通用户角度，问题是“不知道查哪里、不知道怎么处理、不能确认是否解决”。从产品经理角度，本版以完成一次有效处理并读懂结果为目标。空间册继续服务定位与理解，不新增健康分、加速承诺、定时清理、重复文件删除、迁移或增长监控。

## 实现和范围

1. 清理首页进入分析，默认选后端识别的系统卷；手动开始，允许常用目录或原生选择目录。
2. 带盘符的本地固定卷中，NTFS 且可以验证身份的位置可分析。其余显示原因；普通权限读取元数据，拒绝重解析点、云占位与跨卷挂载。
3. 根层先出现、统计逐渐填充，未遍历为“待统计”。未知总量不显示百分比。列表由用户刷新；取消需后端确认。
4. 用途依据与处理入口邻近。仅查看类别不会改变勾选；明确加入才合并下次扫描范围，必须重新扫描。长期排除草稿仍按既有核对流程保存。
5. 扫描候选、已选候选和后端阻止原因分别解释。六条微信、QQ、WPS 规则仍只读，退出应用不解除验收限制。
6. 文件定位失败保留已读内容、勾选与再次定位入口。返回分析保留视图、查询、页码及滚动位置。
7. 当前目标盘空间与查询时间可刷新；只有同一卷身份的样本才相减，称为观察变化。清理报告继续记录自己的实际删除量与各卷采样。
8. 数据库初始化失败时提供保留实际错误的原生提示，可打开 Windows 存储设置。不会绕过日志删除或自动覆盖数据库。
