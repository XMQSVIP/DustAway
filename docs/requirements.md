# 产品需求说明

适用范围：当前首页清理与受限自选删除源码（0.18.0 基础），不是新的发布包。共72条用户扫描规则，34条按条件逐文件清理、1条uv官方整理、37条只读；18条应用规则中仅钉钉网页与代码缓存对固定文件版本8.2.0.119各有独立真实许可，默认不选，普通首页真实闭环待完成。自选来源独立于规则，证据见[当前验收](verification-home-cleanup.md)。下方版本增量为历史要求，发生冲突时以本段为准。

## 产品目标

普通用户通过“开始扫描 → 清理已选 → 一次确认”完成清理，建议自动选择，明细和技术信息默认折叠。进阶用户可取消类别或文件，在空间分析中选择普通文件及完整子树，加入同一清单统一确认。仅删除扫描时发现、后端再次验证的文件，最后尝试删除身份一致的空目录。个人资料绝不自动选择，不以用途标签代替删除资格。

扫描观察版本与逐规则真实清理验收版本分离；只有真实非零清理、保护资料核对、正常复启与功能确认、缓存再生成通过，才允许加入准确规则/版本许可，随后完成普通首页闭环才计交付。其余规则和版本继续只读，自选入口不能绕过。微信日志本轮跳过，不调整时间或保留期限。

沿用完成判断要求：结果入口按状态定位，跨类别按数量排列；仅当正常终态、分类计数一致、没有失败/不确定/未处理且执行保留原因完整属于明确保护类时允许结束处理。未知或缺失原因保持待核对。明细与报告绑定当前会话，历史不借用新扫描，具体规则见 [0.13 研究](user-research-0.13.md)。

拂尘帮助 Windows 普通用户检查并清理可识别的临时文件和浏览器缓存。用户应能在删除前理解范围和影响，删除后知道哪些成功、哪些被保留，以及原因。

成功标准是扫描可解释、选择可核对、删除范围受控、失败可理解。扫描速度、程序文件大小和内存占用需实测，不设置未经验证的宣传指标。

## 功能需求

软件卸载面向用户的主流程为“选软件 → 卸载 → 自动检查残留 → 选择清理或暂不清理”。技术能力、安装信息和完整统计按需展开；自动核对和只读检查不要求用户逐阶段点击，结果不确定时才突出复核入口。缓存与资料仍默认不选，缓存批选仅限本页可清理项；返回列表不删除、不重放任务。简化呈现不改变请求受理、独立清理确认、恢复或文件身份保护。

软件卸载的当前增量见[软件卸载与支持范围](software-uninstall.md)。商店残留必须独立核验当前用户包数据的归属，不能仅凭包族目录授予权限；共享容器成员在卸载后仍可能存在，需在准备、扫描和删除前核对。查询缺失、关联包或共享关系不明时保留数据，标准卸载能力独立判断。此要求不放宽现有普通清理规则。

商店残留操作前还须核对当前用户相关进程，包含其他会话和安装目录内的无包身份子程序。仍运行与读取失败分别保留；不使用进程名猜测包身份、不强制结束程序。枚举和残留处理都必须响应原有停止标识，旧内存上下文不能补出新的进程核验权限。

商店 LocalCache 的系统含义是“不参与备份与恢复”，可能保存长期应用资料，必须归入“设置与本地资料”并触发资料删除确认，不能按名字自动归为缓存。TempState 的临时缓存能力独立；分类、范围或版本变化使旧规则证据失效，不新增删除授权。

残留规则按独立范围与核验版本逐项开放，不因一个测试批次的部分成功而开放其他范围。目前 Firefox 程序版本 `140.17.0.1158` 的缓存、两项设置、Cookie、历史、站点存储、书签备份及会话备份八条规则已取得实机删除证据，并通过生产入口和真实重新安装保护复测。后两条使用另行生成并解码核对的真实浏览器备份，独立绑定证据。其他版本和产品仍保留；这些许可不授权普通清理，也不代表全部产品或每条规则的真实界面删除流程验收完成。

## 标准用户流程

```mermaid
flowchart LR
    Scan[主动全面只读扫描] --> Preview[区分发现占用与可清理量]
    Preview --> Select[核对候选并选择允许清理项]
    Select --> Plan[生成清理计划]
    Plan --> Confirm[确认永久删除]
    Confirm --> Execute[逐项验证并执行]
    Execute --> Report[查看结果]
    Plan -->|返回检查| Preview
```

启动不自动扫描。浏览器运行时可以看到扫描结果，但对应类别不能进入有效清理计划；完全退出浏览器后可以重新检查应用状态。改变清理排除项使当前扫描和计划失效；外观修改不影响会话；改变本次选择后必须重新生成确认计划。

未获得扫描总量时不显示虚构百分比。候选文件大小、已删除文件大小和每个受影响卷的可用空间变化分别展示，不把三者等同。采样失败显示缺失，负差值原样保留；旧报告标明原系统盘口径。

## 当前非目标

- 不自动选择下载、桌面或文档中的个人资料；主动自选仍受系统、安装与核心应用资料保护边界约束。
- 不提供注册表清理、启动项管理、重复文件或相似媒体自动删除。软件卸载与残留检查见[功能说明与支持矩阵](software-uninstall.md)。详情分别展示标准卸载可用性、缓存/设置/本地资料的检查与清理能力，以及缺失的登记信息；描述和旧历史不授予残留删除权限。
- 不直接删除 WinSxS、Windows Installer、驱动仓库或 Windows 更新目录。
- 不清空回收站，不安排自动定时清理，不强制结束应用，不夺取目标所有权或修改目标 ACL。
- 不安排开机续删，不进行文件粉碎，不接受用户删除脚本或在线规则。
- 不保证便携版、自定义浏览器路径、网络盘、云目录和未确认的重定向配置可清理。

## 数据与体验要求

候选明细按会话保存在内存 SQLite 中，界面每页最多 200 项并虚拟渲染。索引需支持 10 万候选项分页；真实磁盘扫描的响应性另行验收。进度查询采用约 500 ms 间隔，每个 Engine 一个扫描线程，删除串行执行。

历史摘要默认采用 30 天保留期，在启动/恢复和历史读取时清理过期终态记录，不清除运行中报告，历史接口最多返回最近 100 条。诊断导出不含候选路径。临时扫描明细不写入历史数据库。

界面要求键盘可操作、焦点可见，兼容系统减少动画和强制颜色设置。实际 100%–200% DPI、屏幕阅读器和高对比度仍需在目标系统测试。

本轮验收免安装启动、普通用户闭环、数据兼容和异常处理。Windows 11、缺少运行时、DPI 等真实环境分别记录；系统提权和安装升级移出当前交付要求。未完成正式发行验证与签名时不标记为正式发行。详见 [路线与状态](roadmap.md)。

## 0.4 增量要求

- 查询 10 秒、命令受理 15 秒等待上限，不限制任务实际运行时间；原生选择对话框除外。
- 请求版本与回执核对，迟到命令不得影响下一次操作；停止绑定任务，不重复删除。
- 实际遍历条目与候选分别统计，保留扫描中断结果但禁止据此生成计划。
- 清理后展示本次结果，未选择文件不归入未处理；手动重扫才确认当前剩余。
- 兼容现有设置、偏好、历史和路径安全边界，沿用文件夹交付，新增规则默认关闭。
## 0.5 增量要求

- 常用位置和原生目录选择器启动单目录只读分析；启动不自动扫描，不提供整盘入口。
- 独立分析会话、分页目录索引、大小排序、当前层级名称搜索和受限定位，分析节点不能授权删除。
- 分析只读取元数据；普通权限、本地固定 NTFS、不跟随链接或召回云文件。允许统计正在使用的文件、只读属性与硬链接。
- 整体按卷/文件身份去重，目录行展示文件条目合计并提示共享。扫描上限 50 万条、128 层；达到上限、取消、读取失败保留不完整状态。
- 分析与清理互斥，复用回执核对与任务恢复；页面切换保留进程内结果，退出不保存路径。清理执行后标记分析陈旧。
- 清理报告按实际受影响卷采样当前用户可用空间，保留负值与失败；兼容旧历史系统盘口径。

## 0.6 增量要求

新增 Brave 与 Vivaldi 六条默认关闭的规则，注册表统一识别标准配置、缓存叶目录和对应进程。旧选择不扩大；新增类别经过独立扫描与显式确认。官方程序与隔离配置实测缓存生成、删除、重建和保护数据，未通过不能标记为已验证。国内三款应用在 0.6 仅提供通用处理指引；0.9 增量见下文，不识别或删除聊天/文档正文。

## 0.7 扫描完整性要求

近期保留预筛不能授权删除。部分受支持位置无法读取时保留问题原因、显示不完整，允许用户确认已完整校验的候选；所有受支持位置读取失败、规则边界无法验证、取消或应用状态未知时阻止相关清理。计划、执行结果与历史持续说明扫描范围，旧记录缺少完整程度时不得推断完整。检查条目包含目录，问题次数不等于未读取文件数量；不估算未知容量或扫描百分比。

## 0.9 应用覆盖与验收要求

历史0.9优先匹配单一程序版本；当前扫描按可信身份与已识别布局匹配，删除版本验收独立。原有微信运行日志/崩溃转储、经典 QQ 三类网页缓存、WPS 运行日志继续保留。全部默认关闭，文件格式与保留期限后端固定。安装目录与扫描资料目录分别识别；缓存与诊断资料分别说明影响。未知版本、身份无法核验、进程无法查询及验收未完成均阻止计划。

运行中可只读扫描，退出后手动重查，保留候选与本次选择；升级或文件变化需重扫。候选逻辑大小、近期保留原因/数量与本次已选量分别显示，不估算未知保留容量。应用内处理结果不计入拂尘删除成绩。

真实应用测试仅限独立环境和测试资料：验证缓存重建、登录和网页持久数据保留、日志重新生成、正常启动，以及非目标文件内容和修改时间不变。六条规则当前尚未通过该验收，只读能力先交付；夹具通过不能解除删除限制。

## 0.10 空间告急范围

保留默认清理页和主动扫描。磁盘选择只限定分析与复核目标，不把跨盘候选总量当作目标盘收益。所有用途和清理资格来自后端；未知位置不称为垃圾。仅查看类别不改变选择，显式加入下次扫描必须保留原选择并使旧计划不可执行，排除草稿继续按既有核对流程处理。

只读本地固定 NTFS 根入口由后端登记；盘符消失、重新映射或身份变化使旧令牌失效。不跟随重解析点、云占位或跨卷挂载，不增加管理员权限。根层优先、深度超限继续、部分结果保留；索引上限 50 万条、128 层、每页 200 项保持。

支持清理、只读扫描、当前不支持与应用进程状态分别呈现。六条应用规则未完成验收，关闭应用也不开放删除。目标盘样本只在当前进程保存，刷新后只能与同一卷身份的有效基线比较；其他程序活动包含在观察变化中，不进入删除成绩。

数据库初始化失败必须在窗口创建前提供原生恢复入口并保留实际错误；单实例检查先于数据库恢复，重复启动不得恢复另一个运行实例的日志。没有数据库迁移、自动重建或无日志删除。首次五名非开发者试用尚待用户安排，不以公开帖子代替真实访谈。


## 0.11 紧凑空间册

默认前三条空间条带，可展开至八条；长度相对本页最大项，待统计中性显示，部分大小标“已读取至少”。结果来源和分析时间固定可见，位置折页完成后收起。1100×780 中三条摘要与首条完整明细同时可见，窄窗口独立滚动且底栏固定。用途、统计完整性与操作资格分开表达，未知或部分统计不授权删除。

待选范围改变时旧结果折叠；新分析受理才替换。刷新失败保留同范围页面及时间，不以错范围缓存填补新查询。同卷空间变化以卷身份区分，失败保留带时间的旧值。清理后提示先核对空间并返回原工作，再决定是否继续。实际性能、环境与人工试用状态见 [0.11 验收](verification-0.11.md)。

## 0.12 清理决策与完成体验

总览、分类状态与底栏复用同一前端决策模型，继续使用既有后端摘要与 BigInt 选择统计。可核对容量不包含受阻或只读候选；未选类别不影响主建议。查看类别不改勾选，同一应用可展示多种状态；新类别和失效会话必须重扫。

请求状态不明先只读核对；报告不确定项先查看报告；失败、跳过和未处理分别说明；其余报告优先复核空间。再次删除必须重新扫描、计划与确认。首页在初始化后、关注位置变化、分析完成、报告终态或手动刷新时查询空间，无定时轮询，失败保留旧读数时间。
