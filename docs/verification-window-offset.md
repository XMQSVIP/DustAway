# 自动测试窗口内容偏移

日期：2026-09-30。

## 复现与原因

在本机 Windows、125% 原生 DPI、WebView2 154.0.4258.37 下，向 EdgeDriver 直接发送 `POST /session/{id}/window/rect`，仅指定 760×580，会把页面报告的屏幕位置从 (481,166) 改成 (962,332)。原生探针确认：外层 Tauri 客户区仍为 1375×975 物理像素，左上角位于屏幕 (601,207)；Chromium 内容子窗口却变成相对客户区 (601,208)、大小 950×725。父窗口没有按请求缩小，内容在窗口内发生偏移。

原驱动为 153.0.4234.48，确有版本不匹配警告。换成微软签名有效的 154.0.4258.37 驱动后仍复现同样偏移，因此版本不匹配不是这个问题的充分解释。根因位于自动测试的窗口调整路径，不能用 CSS 位移补偿。

## 修复

- 桌面测试共用 `desktop-driver.mjs`，拦截尺寸调整并调用原生探针，只调整精确 EXE 路径对应进程的顶层窗口。
- 根据窗口 DPI 把逻辑客户区尺寸换算为物理尺寸，保持屏幕位置、层叠顺序和焦点；拒绝对最小化/最大化窗口或不属于预期进程的窗口执行调整。
- 调整完成后检查原生客户区、WebView 子窗口原点/大小以及 DOM 视口，阻止“网页内部布局通过但整体已偏移”的漏检。
- 创建会话时拒绝驱动与运行时前三段版本不一致，避免继续使用已失配的驱动。

改动只涉及测试工具和验证文档，不改变应用页面、业务逻辑或发行程序。

## 验证边界

新增只读桌面回归：浅色/深色，两次往返 760×580 与 1100×780，共 8 次尺寸调整；同时检查窗口位置、原生子窗口边界、DOM 根节点与视口，以及后台版本、扫描任务和报告没有变化。执行结果保存在 `artifacts/window-offset-regression/result.json`，截图为 WebDriver 页面截图。

原生 Computer Use 截图两次超时，本轮以 Win32 实际窗口坐标和边界作为原生验证依据，不声称完成原生截图目视验收，也不外推到其它系统 DPI。旧验收记录中的网页截图/布局通过不能单独证明外层窗口显示正常。
