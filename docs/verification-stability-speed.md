## 实现

- 私有 SQLite 增加 `(parent,id)` 索引。显式文件按 ID 读取；目录使用有界深度优先批次，只遍历选中子树。最近的显式覆盖决定范围，排除子树内重新勾选的节点成为独立根，父子重叠只遍历一次。摘要和准备共用范围遍历器；临时身份表继续去重。
- 每批至多 256 项或 8 MiB 冻结记录。目录链在批次内复用，离开索引锁后才进行文件系统核验；分页不再等待整个准备过程。每批及提交前验证会话、失效状态和取消标志，取消或变化时丢弃未完成清单。
- 准备与取消带相同 `preparationId` UUID，独立于扫描、摘要和删除状态。操作守卫覆盖完整准备；旧标识不能终止不同标识的新操作。停止先到时只记住对应 UUID（至多 128 项），随后同标识准备立即终止；达到上限明确拒绝，不静默丢弃已受理的停止请求。UI 等待准备实际返回，保留选择，不展示部分清单。
- 相同有效选择已完成的摘要跨准备和取消确认保留；未完成摘要在准备期间停止。统计中仍可勾选或进入最终核验；超过两秒显示已用时间。排除设置保存、候选加入排除和分析失效同时使旧分析/摘要失效，外观设置不影响选择。
- `cleanupResultSummary` 统一完成页、摘要和历史判断；文件/目录分别统计。不确定或计数矛盾优先显示“部分结果尚未确认”；停止、失败、未处理及异常保留显示“清理已结束”。非法数字显示“统计不可用”，合法矛盾数值不修改；旧报告缺少可选目录或分类明细不直接判损坏。只有空目录成功也显示“清理完成”。
- 原生回归中发现先前任务的恢复提示会残留到新的成功结果页，已修正提示的适用状态，并在新准备开始时清除旧提示；最终四组桌面流程均验证残留提示消失。
- 保留执行阶段的文件身份、完整时间、属性、父链、保护及排除重验；统计不成为删除凭据。未增加任意路径参数、删除来源、运行时授权或历史 JSON 必填字段。

## 性能

同一台非提升权限的 Windows 10 19045 x64、i5-10400（12 逻辑处理器）、约 16 GiB RAM；Rust 1.97.1。基线和优化 debug 使用同一 benchmark、相同合成数据和构建 profile，各三次取中位数；release 单独列出。数据为 50 万条记录（2 个目录、499998 个 1 字节文件），准备使用合成平台核验，不访问真实文件。索引时间包含合成扫描和索引构建；不包含编译。摘要不包含前端 300 ms 合并等待。

| 测量 | 基线 debug | 优化 debug | 优化 release |
|---|---:|---:|---:|
| 建立索引 | 34.672 s | 38.975 s | 10.608 s |
| 全部已选摘要 | 37.000 s | 6.897 s | 1.935 s |
| 仅 1 文件摘要 | 1429 ms | <1 ms | <1 ms |
| 仅 200 文件摘要 | 1455 ms | 17 ms | 7 ms |
| 全部清单准备 | 61.966 s | 19.774 s | 6.303 s |

完整 debug 摘要缩短 **81.36%**，超过至少 50% 的目标；合成准备缩短 **68.09%**。新增索引的建立时间中位数增加 **12.41%**，没有把该成本隐藏到摘要中。单文件 0 ms 是毫秒计时截断，表中按 <1 ms 表示。

原始三次结果和中位数：`artifacts/stability-performance.json`，对应 `stability-baseline-debug.log`、`stability-optimized-debug-final.log`、`stability-optimized-release.log`。首次优化 debug 测量在本机内存紧张时第三轮索引建立超过原 60 秒等待上限，保留于 `stability-optimized-debug.log`；未将其两轮结果混入最终三轮中位数。仅将合成 benchmark 等待上限提高到 240 秒，没有放宽产品资源限制。机器有其他应用负载，不能据此承诺其他硬盘、目录形状或系统调用延迟。
