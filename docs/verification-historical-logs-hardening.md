## 本轮实现

安装发现、签名、资源读取与进程观察抽为内部探针。生产与夹具执行同一身份和进程判定代码；测试不再直接返回“已验证身份”或合成指纹。程序、父目录和日志指纹均来自实际临时文件与 Windows 句柄。可变测试实现仅存在于 cfg(test)，清理入口继续验证临时目录身份、固定位置、标记快照与单条规则许可。

ToDesk 仅从 ToDesk.exe App Paths、DisplayName 明确匹配 ToDesk 的卸载登记和既有固定默认位置发现安装。登记不存在与读取失败分别处理；无关软件的安装路径不读取。重复线索按卷与文件 ID 合并，登记有记录但程序缺失、登记信息不全、相关候选失败和多个有效安装均拒绝。先核验发布者，再读取产品和版本；签名失败时产品、版本调用计数必须为零。钉钉继续走既有身份组合、发布者与安装布局判定。

每次进程判断只消费一份快照：主程序跨会话识别，共享辅助程序核对映像归属，同会话安装目录内组件同样阻止清理。无法确认映像或会话归属时保持未知；已经确定目标运行时优先报告正在运行。准备计划和逐文件删除重新查询，不沿用扫描时的“已退出”结论。

单个固定目录、枚举条目或文件元数据读取失败只增加现有范围问题，继续其他位置。存在成功读取（含完整枚举的空目录）时使用 Engine 的部分完成状态；所有实际读取范围都不可读时失败。未知文件大小保持未知，近期、占用、排除、缺失与链接保留不混为读取失败。部分结果仍须使用现有明确确认流程。

扫描在观察调用前后、枚举迭代之间以及连续 Windows API 之间检查取消；不能中断正在执行的同步 API，但其返回后不继续下一项工作，必要句柄与 WinTrust 状态释放除外。Engine 在已取消扫描后不再开始新的安装/进程查询。取消不增加范围读取失败，取消后不发布新候选。准备与执行的检查没有放宽。
