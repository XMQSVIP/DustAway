# 拂尘 0.9：应用覆盖的双视角研究

本轮选择：微信、经典 QQ、WPS；允许可重建缓存与过期诊断文件；本机版本优先。研究方法为公开用户求助、官方说明、代码审查及本机只读元数据盘点，没有真人访谈或代表性需求占比调查。

| 使用者的问题 | 证据与局限 | 产品决策 |
| --- | --- | --- |
| 常用软件占用很大，但工具只有浏览器清理 | 0.8 源码仅有通用指引；这属于工程观察 | 增加三款应用、六条候选规则，分别展示支持与验收状态 |
| 微信新旧目录看起来占两份空间 | [腾讯官方迁移说明](https://support.qq.com/products/292433/faqs/162247)说明同分区附件可使用硬链接；不能推断任意两份目录都共享 | 不删除历史聊天目录，保留硬链接保护，指引进入微信管理 |
| WPS 缓存、备份和插件难区分 | [公开用户帖](https://forum.wps.cn/topic/90864)是用户经验，不是安全删除契约；[版本公告](https://forum.wps.cn/topic/93227)描述新版存储管理 | 本轮仅适配旧版日志；新版菜单说明标注版本，不承诺旧版存在同一入口 |
| 关闭窗口仍不能清理 | 本机后端识别出 WeChatAppEx、crashpad_handler 和 TXPlatform 等组件 | 检查已知进程及安装位置下可识别的后台组件，显示组件名并允许重查 |
| 扫描数字很大，实际收益小 | 本机只读盘点 QQ 三类缓存约 1.1 MiB，微信满 7 天 xlog 约 207 MiB；样本随使用变化且尚未完成删除验证 | 不宣传固定释放容量；诊断文件单独分类，近期保留与阻止原因明确展示 |
| 版本提示与实际程序不一致 | 微信卸载项自报 4.0.6.17，签名有效的程序实际版本为 4.1.13.65 | 注册表仅定位，以二进制版本、离线签名及固定布局共同判定 |

## 技术依据及限制

- [CEF 官方类型定义](https://github.com/chromiumembedded/cef/blob/master/include/internal/cef_types.h)表明缓存根也可以承载 Cookie、localStorage 等持久数据。QQ 的 webkitex_cache 整体不能删除；本轮只匹配三个叶目录。
- [Tencent Mars 文档](https://github.com/Tencent/mars/wiki/Mars-%E8%87%AA%E5%AE%9A%E4%B9%89%E6%89%A9%E5%B1%95)说明 mmap 与异步日志有关。它不是微信当前版本的完整目录契约；本轮额外保留 mmap、mmap3、ini 及未列入格式。
- [微软转储说明](https://learn.microsoft.com/en-us/windows-hardware/drivers/debugger/user-mode-dump-files)将转储用于故障诊断。删除过期转储会损失过去的排障资料，不描述为“可重建缓存”。

## 本轮结论

六条规则已经实现固定范围和只读扫描，但真实应用删除、缓存重建、测试登录/资料保留尚无隔离验收证据，因此发行版全部保持不可执行。这一状态不可通过界面、环境变量或关闭应用解除。测试夹具不构成真实应用验收；未通过时不能宣称已经扩展直接删除范围。

真人后续观察任务：找到应用版本及扫描磁盘；解释“候选”和“已选”的区别；理解 7/30 天保留期；关闭窗口后识别后台组件；正确解释“待验收”不能通过重试解除。工程任务走查与真人理解度应分别记录。
