# 0.12 双视角研究与取舍

日期：2026-09-27。本轮采用源码审查、已有实际桌面截图与公开资料，没有访谈样本、需求占比或真实试用完成率。

## 用户视角

| 使用情境 | 真实需求假设 | 本轮改进 |
| --- | --- | --- |
| 安装或保存受阻 | 有效处理后回到原任务，知道何时可以停止 | 结果优先、当前空间与次要重扫 |
| 看见大缓存不敢删 | 明白影响与保留范围 | 候选旁简短影响、明确只读能力 |
| 浏览器正在工作 | 先处理其他类别，不被迫退出 | 混合状态、独立应用状态重查 |
| 扫到微信/QQ/WPS | 知道是否真的能删 | 只读独立说明，不进入可核对容量 |
| 清理后空间不增 | 区分文件删除与空间观察 | 分开时间、口径与失败项 |
| 没有候选 | 分清查不到、未选与查不完 | 明确不同状态和操作 |

[公开用户求助](https://www.reddit.com/r/WindowsHelp/comments/1h9jl9j/can_anyone_spot_the_obvious_eliminations_to_free/) 中的发帖者使用空间分析工具后仍担心删除浏览器数据；只作为个例，不采纳回复中的任意系统目录删除建议。

[Google 官方缓存说明](https://support.google.com/accounts/answer/32050?co=GENIE.Platform%3DDesktop&hl=en) 说明缓存帮助再次访问，清除后内容需要重载。这支持说明清理代价；Cookie 和缓存不同，不据该页面把二者一起纳入本工具范围。

[微软释放空间说明](https://support.microsoft.com/en-us/windows/experience/storage-filemanagement/free-up-drive-space-in-windows) 涵盖临时文件、应用与个人资料等不同处理途径。本工具沿用分析和固定系统设置入口，不把所有占用叫作垃圾。

## 产品经理视角

源码确认：原建议按全局原因选择一段话，难同时表达混合状态；报告出现后刷新空间优先于失败处理；空间查询直到进入分析才激活，首页刷新可能变成页面跳转。旧最小窗口截图里，大空间卡片挤占结果首屏。

本轮以独立完成合适操作、理解结果与决定是否继续为目标。优先统一决策、呈现混合状态、明确结束点。保留空间册、不扩大清理权限和规则。前端模型只组织展示，最终计划与执行授权仍在后端。

衡量：任务完成、理解错误、求助与无效重扫；不以删除 GB 或使用时长为单一成功指标。五人试用尚待开展，目标与记录见 [试用脚本](usability-0.12.md)。
