# 网盘与下载工具：用户需求与产品取舍

日期：2026-09-29。本轮承接办公通信扩展，面向普通用户增加百度网盘、夸克网盘与迅雷的只读发现和资料解释。真实用户访谈/试用人数仍为 0，下面是源码、本机元数据、公开资料与场景分析形成的待验证判断，不是用户发生率。

| 用户使用角度 | 产品经理角度 | 本轮落地 |
| --- | --- | --- |
| “网盘占了很多空间，哪些能动？” | 软件名下混合缓存、下载、离线资料和状态，按整个目录估算收益容易误导 | 只匹配 7 个明确缓存叶目录；说明“发现占用”不等于可清理 |
| “下载了一半的文件是不是垃圾？” | 删除任务中间文件可能造成时间、带宽损失 | .xltd 只解释可能未完成，引导回迅雷核对，不提供删除或改名 |
| “文件已在云端，本地都能删吧？” | 路径和本地大小不能证明同步完成、云副本有效或离线需求消失 | 不判断云端状态；配置根目录与持久存储明确保留 |
| “刚清过，为什么又有缓存？” | 再增长是应用行为，不能把重复清理次数当成价值 | 说明可能重新生成、重新下载及首次加载变慢 |
| “为什么支持软件却没有结果？” | 空目录、位置缺失、身份失败和部分读取含义不同 | 保留各类覆盖结果；夸克、迅雷本机空样本不冒充真实候选验收 |
| “关掉软件就能清了吗？” | 用户退出正在使用的程序有中断成本 | 运行状态与只读能力分开；新规则始终默认不选，不能进入清理量 |

优先级按实际发现价值、范围可信度和验证成本决定。本机百度三个目标目录的元数据合计约 17 MiB；夸克、迅雷四个目标目录存在但为空，且未观察到 Cache/Cache_Data。因此提供只读发现准备，不添加没有已核实布局的网页缓存规则，更不扫描整个 Cache。这里是单机观察，不预测其他用户收益。

公开讨论提供需求线索：[百度缓存数据库读写疑问](https://www.v2ex.com/t/1135110)（2025-05-29）说明用户难以理解后台活动，但不能证明持续异常；[夸克旧版写入讨论](https://www.v2ex.com/t/955422)（2023-07-10）是历史个案，不据此评价当前版本。[迅雷官方社区回复](https://bbs.xunlei.com/circles/12/posts/35258)解释 .xltd 与未完成下载有关。这里不采纳帖子里的修改权限等解决办法。

[Electron 官方 sessionData 文档](https://www.electronjs.org/docs/latest/api/app#appgetpathname)说明配置数据可能包含 Cookie、磁盘缓存、网络状态与本地存储，支持“不能清空整个配置根”的判断；不以该通用文档证明三款应用的私有路径。[夸克产品页](https://pan.quark.cn/)中的备份与下载用途，也提示离线资料具有用户价值。实际扫描路径来自本机元数据核对，不读取数据库、账号或 Preferences 正文。

本轮成功标准：正确解释范围，7 条规则在合成样本发现候选，18 条应用规则证据完整，原有 14 条条件清理回归通过；不以新增规则数、发现总量或零候选宣称释放空间。真实删除、缓存再生成和保护资料复核继续待执行，见[支持矩阵与操作单](support-matrix-netdisk-preparation.md)；理解程度通过[五人任务脚本](usability-netdisk-preparation.md)后续验证。
