## P0 清理主线

- 保留默认 C 盘、多磁盘选择和既有视觉；继续按“建议清理／可自行选择／已保留”组织，再按用途和应用归并。
- 可操作用途分组按可选容量降序；展示文件数、可选容量、已选文件数和容量。零候选继续隐藏，读取问题仍有原因。
- “选择建议项”只作用于当前允许且可选择的建议规则。展开分组不选择文件，不包含日志或附件。详情、路径、定位和一次确认继续复用原流程。
- 回执区分已删除逻辑字节、保留或失败原因及逐盘可用空间净变化，不将扫描量视为可释放量。
- 微信日志仍满 7 天，微信转储、旧应用转储、归档错误报告仍满 30 天，默认不选。测试机分别发现 18、2、7、0 个文件，均无满足时间门槛的样本。本轮不伪造文件年龄，不把隔离测试当成真实诊断资料验收，四项继续只读。旧应用转储此前凭用途文档开放的入口收回，后端与前端投影同步收紧。
- 应用缓存延续逐应用许可。已有共享缓存研究发现零散删除网页响应文件可能造成首次访问失败，相关规则仍只读；没有从某应用的行为推导其他应用同样可删。历史研究见 [缓存依据](readonly-cache-evidence.md)。

## P1 支持范围

独立入口“聊天附件整理”要求用户选择已识别账号位置，再主动扫描；普通垃圾扫描不会遍历聊天附件。默认按最后修改时间超过 30 天筛选，支持 90 天、180 天、全部、类型和文件名，按大小降序，每页 100 项。全选仅作用于本页可选附件；已选清单跨页、跨筛选保留。图片／视频提供本地缩略图与放大预览，文件／语音用列表，详情可显示完整路径并定位。

当前按可信安装与已验证布局许可，历史实机样本为 **Weixin 文件版本 4.1.15.13**，`xwechat_files/wxid_*` 当前 Windows 用户所属账号、已验证的 `db_storage/message/message_0.db` 与 `msg` 布局，以及以下独立文件：

| 位置 | 格式 | 状态 |
| --- | --- | --- |
| `msg/video/YYYY-MM/` | MP4 视频、JPG 视频封面 | 经文件头和身份复核，可主动选择永久删除 |
| `msg/file/YYYY-MM/` | ZIP 接收文件 | 经文件头和身份复核，可主动选择永久删除 |
| 其他已识别位置或格式 | PNG、JPEG、其他视频、语音、PDF 等 | 可浏览，未经独立删除验收保持只读 |
| 加密／未知格式 | DAT 等 | 不解密、不提供删除选项 |

版本更新后重新扫描并核验兼容性；月份目录以外、额外嵌套、其他子目录不继承上述许可。自定义位置仍须满足相同身份、归属、布局和组件一致性核验，选择一个目录不会授予任意路径删除能力。数据库仅读取文件身份元数据，不读取聊天正文，不修改数据库、登录信息、备份或迁移资料。

附件有独立选择与确认流程，按钮明确“永久删除所选附件”，说明本机对应聊天附件可能无法再次打开、不能保证重新下载。准备和逐文件执行都检查微信及后台组件；状态不明或仍运行时保留，不强制退出进程。取消只停止后续删除，不自动续删。

## 实机证据

远程电脑：用户授权的 DESKTOP-24NJTT6 / MSN / Windows 11，严格 SSH 主机记录校验。测试以 MSN 普通交互用户运行，未改动防火墙、网络、UAC 或 ACL。

1. 原始完整扫描发现 **393 个附件、31,546,245 字节**，0 个读取问题。运行中准备被 `application_running` 拒绝，未执行删除。
2. 用户确认从托盘退出微信后，冻结三个已授权样本：一个 MP4、对应 JPG 封面、一个 ZIP。首次核验发现样本均有只读属性，通用文件删除正确拒绝，未创建执行标记。
3. 为附件专用能力加入 Windows 按句柄处理只读文件；不清除文件属性、不修改 ACL、不采用 POSIX 删除，也不放宽空间分析的通用手动删除保护。隔离测试验证普通删除仍拒绝、失败不改变属性、链接仍拒绝。
4. 正式单次测试成功删除 **3 个文件、10,323,944 字节**，失败／跳过／未知均为 0；目录删除为 0。两个预览都成功。一次性计划重放被拒绝。
5. 同账号其余 **1,316 个文件**的大小与 SHA-256 前后完全一致。C 盘可用空间从 **27,644,403,712** 变为 **27,654,729,728** 字节，净增加 **10,326,016** 字节。此数是磁盘采样净变化，不等同于附件逻辑大小。
6. 重新打开微信后，用户明确确认：**“登录、聊天记录和未删除附件均正常”**。这是人工功能验收；原始 `acceptance.json` 保留当时 pending 状态，后续确认单独记录，不改写原始测试输出。
7. 最终收紧账号归属、数据库身份和格式目录许可后，再以普通用户做只读核对：识别 1 个账号，完整读取当时 439 个附件，无读取问题；两个视频预览正常。登录后新增内容不参与此前删除，不将新扫描总量与删除前总量直接相减。

原始机器记录保存在 `artifacts/attachments-real-20261002/`（含样本路径，仅开发验收保存，不随软件包分发）。真实破坏性测试标记 `delete.started` 已创建，**不得删除标记或重跑该测试**。测试源仅在 Rust `cfg(test)` 编译，生产程序没有测试许可开关。

## 架构与删除边界

- 新增 `AttachmentSelection { session, selected_ids }`、会话扫描／查询／缩略图／定位命令；`prepare_cleanup` 的可选 `attachments` 参数不得与常规请求或手动选择混用。
- 前端只能提交会话与候选 ID。真实路径、文件身份、父目录链、应用安装指纹、版本、账号结构由后端保管。单次冻结清单复用已有执行、防重复提交、取消和磁盘采样流程。
- 扫描、准备、执行核对文件身份、父目录、排除项和当前版本；文件变化、目录替换、链接、云文件、占用等拒绝处理；新增文件不进入冻结清单。部分读取失败的会话只读。
- 会话上限 50,000 文件／64 MiB 估算元数据，单次查询 100 项。缩略图在后台线程按可见区域请求，同一时刻只生成一个，内存缓存最多 32 张，每张最多 2 MiB，会话结束释放。Windows 自身可能管理 Shell 缩略图缓存；DustAway 不持久保存缩略图。
- 清理历史兼容新增可选 `source` 字段，附件摘要使用 `weixin.attachments`。不持久保存完整附件清单或正文，失败摘要延续原有有限记录策略。

缩略图使用微软 [IShellItemImageFactory::GetImage](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ishellitemimagefactory-getimage)；视频解码不支持时只尝试同目录同名且格式验证通过的 JPG 封面。只读文件使用 [FILE_DISPOSITION_INFORMATION_EX](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntddk/ns-ntddk-_file_disposition_information_ex) 的忽略只读属性标记，仍要求 DELETE 访问权和固定文件句柄。
