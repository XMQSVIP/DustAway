## 技术证据与约束

- [Rust DirEntry 文档](https://doc.rust-lang.org/std/fs/struct.DirEntry.html#method.metadata)说明 Windows 枚举条目携带元数据，且此调用不跟随符号链接。查阅页为 1.98.1，项目仍固定 1.97.1；在固定工具链上以夹具及实际调用验证，不升级工具链来换取性能差异。
- [Microsoft FindFirstFileExW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-findfirstfileexw)，页面更新 2023-02-09，指出枚举返回的 NTFS 属性可能过时。因此预筛只能保留文件，所有候选及删除仍须按句柄核验。
- 本轮测试确认：占用文件仍可能允许读取属性。候选快照不代表删除已经获准，带删除访问权的最终句柄必须重新检查共享冲突。近期文件即使正被使用，也可以直接保留。

用户选择先解决扫描提速与可靠性；对于部分读取失败，选择明确标注并允许确认清理已验证候选。这个选择不改变应用状态未知、取消、伪造会话或身份变化时的拒绝规则。

## 验收方法与研究局限

性能桥仅存在于 Rust test 构建，固定标记目录且删除方法始终报错。每种负载预热两个版本，各收集五次交替配对样本；近期比例为 90%、50%、0%，另含深目录和大量排除项。候选集合用排序后的路径和逻辑大小生成 SHA-256，对比在完整相同夹具上完成。只读空间分析单独回归，取消记录 20 次样本。

所有原始测量、未达到目标的情况和实际浏览器验证见 [0.7 验收记录](verification.md)。桌面任务验收由自动化执行，不声称已经开展真实普通用户可用性研究。Windows 11、其他硬件、DPI 和辅助技术未执行项目继续单独列出。
