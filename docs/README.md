## 文档维护约定

- 功能行为以代码和可复现结果为依据；未来计划写入路线文档，不混入已实现功能。
- 测试方法放在 `testing.md`，带环境和结果的验收证据放在 `verification.md`。
- 接口变更同步 Rust 命令、TypeScript 类型、调用封装和 `ipc-api.md`。
- 规则变更同步内置 TOML、浏览器预览规则和 `rules.md`，补充相应测试。
- 构建命令以根目录 `package.json` 和 Cargo 配置为准，发布前复核文档中的命令。
- 使用相对链接保证仓库移动后仍可阅读。`target/`、`artifacts/` 中的本机产物不属于源码文档，其他机器需要重新生成。
