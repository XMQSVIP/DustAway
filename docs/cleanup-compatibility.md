# 应用清理兼容性策略

当前源码不以应用版本号或版本范围作为清理白名单。版本继续用于显示、历史验收记录和安装指纹；扫描后安装更新会使旧清单失效，重新扫描后按实际兼容性核验。

## 判断依据

- 每条规则仍需独立的清理依据；已开放的钉钉规则不会给百度、QQ 缓存或其他只读规则授权。
- 微信、经典 QQ、QQNT 分别核验可信安装、组件、账号归属、目录布局和独立文件格式。来源和布局不能相互替代；QQ 两种来源维持原有范围，微信 0.20 的接收文件格式扩展见 [专项验收](verification-weixin-special.md)。
- VS Code 核验微软签名、产品标记、启动器与包版本一致、当前构建标识及缓存格式，不再固定为 1.134.0。
- PyCharm 核验 JetBrains 签名、产品与 build.txt 一致、JCEF 元数据与 DLL 一致；只允许该安装声明的 `JetBrains/PyCharm年.版` 下原有 JCEF 缓存位置。其他产品、资料目录、IDE 索引、Local History 和未知格式保留。
- 卸载残留仍匹配已开放规则的完整范围摘要、应用身份或精确商店包族；历史样本版本不再限制当前版本。重新安装、安装身份变化、未退出等检查保持有效；没有新增其他产品或商店包许可。
- 官方工具入口改为查询实际命令帮助，核对 Go 的 `clean -cache`、Yarn 的缓存操作与固定参数、ccache 的按年龄整理参数；pnpm 适配器也取消主版本判断，但其现有只读规则不因此开放。查询不运行清理命令，布局与安装指纹仍须匹配。
- 缓存格式版本、内部规则版本、会话契约版本仍严格检查。它们描述解析方式与操作范围，不是应用发行版本。

Cherry Studio 当前官方样本未签名，必须通过官方程序与 app.asar 的 SHA-256 核验来源。已移除其独立的版本号判断，但未知、未签名程序仍不能建立可信身份，因此保持只读。不能用文件名或版本字符串代替来源核验。

## 更新与执行

扫描、准备和逐文件执行继续检查安装及文件身份、父目录链、布局、排除项、运行状态、链接、云文件、占用和修改情况。更新过程中组件不一致时保留；更新完成后重新扫描，核验通过即可使用原有规则。不会沿用更新前冻结的删除计划。

界面区分“清理验收样本”和“当前核验结果”；样本版本是历史证据，不宣称所有未来版本均已实际测试。旧后端或历史记录中的拒绝理由仍被识别。
