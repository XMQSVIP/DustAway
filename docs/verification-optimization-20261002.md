# 构建空间与分页优化（2026-10-02）

本轮针对累计编译输出过大和分页路径中的重复工作修改源码，不覆盖此前 R3 测试包，也不以新测量替换旧验收的失败样本。

## 实现范围

- 工作区与独立分析 harness 的开发构建使用有限调试信息并关闭增量编译；测试继承开发配置。Release 的优化级别与 LTO 保持不变。不能仅凭配置保证磁盘占用上限，切换工具链/功能仍会积累产物。
- `scripts/build-cache.ps1` 默认只报告仓库本地 `target` 的逻辑占用，显式 `-Mode Clean` 才删除选定构建目录，支持 `-WhatIf`。检查绝对目录链、内部重解析点及编译/项目进程；不跟随外部构建缓存配置，不强行结束进程。使用方法见[开发指南](development.md#构建缓存与磁盘空间)。
- 详情、父路径、父链、手动清理能力和目录聚合查询复用连接内的预编译 SQL。文件不再执行只对目录有意义的聚合查询；判断共享文件身份时找到第二条记录即停止，不统计全部硬链接。
- 只缓存最近一次成功的异步计数，完整查询条件（含会话）和 publication revision 均相同时才复用。分页游标、页偏移和请求 ID 不影响计数身份；切换会话清除缓存。缓存不保存文件明细或删除资格。
- 页面组装完毕后先释放读事务，再启动异步计数连接；计数仍重新检查 publication revision。查询取消、游标版本校验及删除前身份检查继续保留。

## 验证范围

原始日志、修改前源码备份和性能 JSON 位于 `artifacts/optimization-20261002/`。新增回归验证跨页复用计数、筛选隔离和同一会话的发布版本失效；原有硬链接、逻辑/分配空间、分页顺序、取消和专用夹具删除回归同时运行。

第一次测试编译因 Windows 集成测试尚未声明 rusqlite 开发依赖失败；补齐依赖后重跑，失败日志保留。只读缓存报告最初遇到 PowerShell DirectoryInfo 父目录没有 PSIsContainer 扩展属性的问题，改为类型检查后重新验证。

核心与 Windows 最终测试共 **278 通过、25 忽略、0 失败**（17 组结果，含空的文档测试组）。随后加强筛选与 revision 两种失效条件的独立断言，磁盘索引集成测试再次 **6/6 通过**。`cargo fmt --all --check` 通过，默认配置以及启用 `analysis-query-timing` 的 Clippy 全目标检查均通过；package.json 格式检查通过。接口和前端没有修改，本轮未重新执行桌面 E2E 或打包。

`pnpm test:build-cache` 验证占用报告、`-WhatIf` 不改变文件、非法范围拒绝，以及中间/内部 junction 拒绝，全部通过。测试首次在当前 Windows PowerShell 环境找不到 Get-FileHash，改为逐字比较小型标记内容后通过；保留首次日志。此测试不实际删除文件。真实项目的清理命令也仅运行 `-WhatIf`，目标为 `target/debug`，源码与 Release 不在该范围。

完成核心/Windows 测试、静态检查和 Release benchmark 后，`target` 逻辑大小约 **1.541 GiB**（debug 1.186、benchmark 0.355）。本轮没有重新构建整个桌面应用，也没有长期切换功能组合，因此不能将它与历史累计 122.37 GiB 比较成固定节省比例。基准会话正常关闭，D 盘专用索引目录仅剩测试标记；没有重新生成百万级文件夹具。

## 性能测量方法

使用已保留的 R3 Release benchmark 与本轮 Release benchmark，同一 F 盘标记的 300 万文件夹具、同一 D 盘 NVMe 临时索引目录，顺序运行。沿用 18 种查询和取消口径，正式测量不开启分段计时。编译完成后再测，不清空系统磁盘缓存；这不是冷盘测试，也不是跨机器性能保证。保留每次二进制哈希、时间及当时编译进程数。

当前改动消除了可确认的重复工作；是否解决此前普通页 P95 678 ms 的间歇延迟，必须根据本轮结果及重复性分别判断，不能由代码改动推定通过。

**结论与限制：** 本轮普通页中位数下降约 37.3%，所有普通页都在 250 ms 内；但这是旧版先、新版后的一组对照，没有清空系统缓存，扫描耗时变化不能全部归因于代码。14 个样本的 nearest-rank P95 等于最大值，不能代表真实用户分布。新版保留了一个 239.457 ms 的搜索慢样本，仍在 2 秒目标内，但不能宣称所有查询都变快。首次页面仍有约 0.58 秒初始化耗时。

旧版在本轮同样没有重现之前 678 ms 的 P95，故**历史间歇延迟仍未定位，原 R3 正式验收未通过的结论不变**。本轮可以确认重复 SQL 和重复计数已减少，不能承诺在任意系统竞争/存储条件下都不出现慢页。
