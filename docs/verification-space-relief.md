## 保留的原始失败与修复过程

1. 初次全量前端运行被中止，首次分页 debug 运行在准备期超时；日志仍在，后续独立重跑通过。12 处既有格式问题保留首次失败日志后修复。
2. 最初计划任务的 `-File` 启动方式未开始测试；改为读取已审阅脚本的 EncodedCommand，权限、执行策略和安全设置未改变。
3. 三项真实 pip/npm 清理均通过后，PowerShell 驱动把应用状态数组误判为错误；没有重跑已完成删除，uv 从单独的新阶段开始。
4. 首次 uv 保护快照拒绝安装环境中的链接，在提交前停止；改为记录链接本身。下一阶段的真实 prune 完成并通过保护核对后，Python `-c` 参数引号错误导致测试脚本失败；此失败未被覆盖。
5. 第一次只读补查又遇到 PowerShell 5 JSON 数组包装错误，未执行清理。修复后在新目录 `uv-postcheck2` 逐个核对保护样本、环境和工具启动成功。真实 uv 的删除操作从未重放。

因此 `real/run.json`、`uv/run.json`、`uv2/run.json` 的非零结果如实保留。逐项真实删除的成功证据与后续只读恢复证据分别列明，不能把整段原始运行改写为从未失败。
