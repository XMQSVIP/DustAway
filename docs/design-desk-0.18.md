# 拂尘 0.18：可展开的整理台

以“层叠留白”形成拂尘自己的视觉结构：顶部四个页签像工作页露出的索引，主体是一张展开的整理台。装饰层从标志的叠片发展而来，数据列表保持平整，避免每一项都变成卡片。

## 体验判断

用户首先想完成清理，而不是理解23条规则。首页只给一个“扫描垃圾”入口、简洁的磁盘读数和按需展开的检查范围。扫描、选择、执行、完成共享一个舞台；结果阶段压缩装饰层，让选择和操作进入视线。

结果只来自实际候选：建议清理、需要你确认、暂不可清理。按应用归组、按类别展示；空分组不显示。零候选但检查未完成单独提示。只读规则不显示复选框，不以退出应用作为解锁办法。

文件明细沿右侧抽出，窄窗口接近全宽，关闭时恢复原入口。全局主操作固定在任务栏；空闲首页不重复底部扫描按钮。用户离开执行页面时仍可返回当前任务。

空间分析默认全范围大文件，用途作为辅助条件；行内条带替代旧的重复图形排行，条带只比较当前页，不表示可释放比例。历史是按日期保留的清理回执，设置是带缩略预览的索引页。

## 视觉与动效

浅色：雾白 #EFF3F1、页白 #FAFCFB、墨绿 #193B36、深青 #196C60；灰绿和砂色用于层片。深色：#122723、#1B3530、#ECF4EF、#A9D8C8。失败与风险有文字标识，不仅依赖颜色。

本机微软雅黑UI与Segoe UI；标题约30–36px，正文15–16px，路径及辅助文字至少13px。叠片采用CSS错位、切角、遮挡和局部阴影；只对位移、透明度作120/240/400ms反馈。装饰不接收焦点，减少动效直接呈现最终状态。无WebGL、粒子场或常驻动画。

扫描层片不表示百分比，完成后的留白不按假定空间绘图。小于960px使用单列信息结构并缩减装饰；760×580窗口保留固定主操作，内容可滚动。

## 业务与兼容边界

`useAppController`和原清理决策模型继续提供唯一业务来源；`cleanupPresentation`只负责页面阶段与三个结果分组。停止中、请求状态不确定优先于成功。`CleanupGroups`、`CleanupRuleList`使用同一候选和选择总量，历史由`HistoryPage`呈现。

保留一次性 `start_scan → prepare_cleanup → execute_cleanup` 流程，只有后端计划可以授权删除。没有新增Rust删除接口、数据库迁移或清理范围。23条规则、9条只读限制均保持。

`dustaway.ui.v3`仅保存动效偏好，从v2继承动效但忽略空间视图与展开度，保留v2原键。主题和排除继续保存到原后端设置。

## 设计依据与尚待验证

来自用户对“未安装软件墙”“23个类别”和通用软件界面的实际反馈，以及现有代码能力。借鉴[Windows清理建议](https://support.microsoft.com/en-us/windows/experience/storage-filemanagement/free-up-drive-space-in-windows)的选择控制、[CCleaner分析明细](https://support.ccleaner.com/articles/en_US/Master_Article/custom-clean-s-analysis-and-results-function)的透明度、[DaisyDisk](https://daisydiskapp.com/guide/4/en/UnderstandingSunburst/)的图形与列表关联；具体构图使用拂尘自己的叠片语言。
