# 0.25.0 独立验收操作单

本操作单不是通过记录。当前真实参与者为零；不把自动化、设计者自查或模型生成的评价记为人工观察。

## 四条候选规则

`stability_probe` 链接普通生产库，只读取指定规则并验证只读计划被拒绝，不调用删除入口：

```powershell
cargo build -p dustaway-windows --locked --example stability_probe
target/debug/examples/stability_probe.exe weixin.code
target/debug/examples/stability_probe.exe weixin.gpu
target/debug/examples/stability_probe.exe appcache.dingtalk_logs
target/debug/examples/stability_probe.exe appcache.todesk_logs
```

必须以普通用户运行。每条输出独立保存；记录程序哈希、机器和运行标识。缺失位置、零候选或生产拒绝不能作为删除成功证据。

使用 `node scripts/stability-acceptance.mjs init <新目录> <规则ID>` 建立独立证据请求。它不授予测试或发行删除权限。`check <目录>` 要求按顺序提供 preflight、protected_before、cleanup、protected_after、recovery、human_observation 六份记录，并通过 evidence.json 中的文件长度和 SHA-256 核验。

各记录绑定同一运行 ID、规则、安装指纹和验收二进制；保护摘要必须相同，实际删除必须非零，失败、不确定和未处理不得冒充完成。微信要求同一网页首次和再次加载、缓存重建及真人功能观察；日志要求真实七天门槛、未改时间、新日志产生与真人功能观察。合成证据及缺失观察者均拒绝完整验收。

本轮只读预检与证据接收器不替代受限实机删除入口；历史实机脚本的主机、日期、安装哈希和运行目录不能直接重放。没有完整证据的候选继续只读。

## 已开放场景

在可还原 Windows 测试环境中，使用专用浏览器配置、测试聊天账号和可丢弃文件，分别完成临时文件、Edge/Chrome 缓存、微信/QQ 附件流程。先记录保护文件摘要与磁盘读数，再经普通界面扫描、选择、确认、核对回执，最后正常启动对应应用核验。Edge/Chrome 配置的网页、登录与站点存储不计为缓存删除目标；不以扫描量代替释放量。

每组独立记录候选、选择、实际删除、保留、失败、不确定及磁盘前后变化。取消、部分选择和文件变化使用可重复创建的专用夹具验证；不重放历史删除计划。

## 五名非开发者

为 P1–P5 分别建立记录，仅保存匿名编号、任务耗时、首次点击、错误、求助和原话。每人使用相同的可丢弃样本，不给予导航提示。

1. 找到扫描入口，并解释扫描是否会删除文件。
2. 找到指定文件并保留它，返回后确认选择仍正确。
3. 区分建议项、需确认项与只读项，解释为什么部分内容保留。
4. 完成一次清理，解释永久删除与文件大小的含义。
5. 找到结果和逐盘读数，解释发现占用、删除文件大小及可用空间变化的区别。

至少四人无需指导完成，五人均理解永久删除和容量区别；不满足时记录实际卡点后修正重测。没有参与者时状态保持未执行。

## 桌面与发行

1100×780 与 760×580、浅深色、键盘与减少动画分别留存原生记录。Chromium 100%/150%/200% 模拟缩放只能说明页面重排，不能代替实际 Windows DPI。安装版与免安装版分别核验，升级保留设置和历史；包哈希和安装载荷哈希分别记录。
