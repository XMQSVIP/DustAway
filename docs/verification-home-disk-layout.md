# 首页磁盘选择布局稳定性

日期：2026-10-01。

问题：从默认 C 盘切换到全部磁盘后，空间读数增加；异步查询结束又移除状态行，网格按内容重新计算高度，使扫描按钮和磁盘选项发生跳动。

调整：仅首页的磁盘读数区预留固定高度；单盘、未选择、多盘、查询和失败状态共用同一空间。多盘读数的状态行保留位置，超过三盘仍可展开，在读数区内滚动，不撑高操作区。保留原有逐盘计量、默认 C 盘和扫描选择语义。

修改前的三个相关文件已保存于 `artifacts/home-disk-layout-before-20261001.zip`，SHA-256 `b4f8a3adf69dad81f4299a47ab798732b08b278b23211b703eea61d5167216f0`。

验证工具：`node scripts/home-disk-layout-check.mjs`。普通开发构建，760×580 / 1100×780、浅色 / 深色；逐帧记录全选、取消全选、单选、多选和刷新的首页高度、操作区高度、按钮位置、磁盘选项位置及页面滚动范围，另检查展开其余磁盘。查询中和失败状态使用测试 WebView 内的合成 DOM 样本验证样式，不伪装为真实磁盘失败；组件测试另行覆盖读取失败的渲染。未改变生产接口，未扫描或删除文件。

修改前，窄窗口操作区最多变化 53.25 px、按钮移动 26.625 px；宽窗口分别为 101.25 px 和 50.625 px。基线记录：`artifacts/home-disk-layout/before/results.json`。

基线脚本早期尝试拦截磁盘查询，但 Tauri 接口只读，注入没有生效；该记录里的 `failed-refresh` 实际是普通刷新，不能作为磁盘失败证据。最终脚本移除了接口拦截，明确区分真实交互和合成样式状态。

最终四组原生窗口各 7 种状态全部通过，操作区高度及扫描按钮位置的最大变化均为 **0 px**；首页整体高度、磁盘选项位置和滚动范围也保持不变，主操作保持可见。展开其余磁盘没有移动操作区。结果和截图位于 `artifacts/home-disk-layout/after/`，已查看窄窗成功及合成失败状态截图，三个默认读数、失败提示和更多磁盘入口均可见。验证环境为本机 125% 缩放，未把该结果推广为所有 DPI 环境均已验收。

相关 3 项组件测试及 2 项磁盘选择集成测试通过，前端构建和修改文件的格式检查通过。集成测试首次 forks worker 启动超时、未执行用例，改用单个 threads worker 重跑后 2 项通过，45 项不相关用例未运行；日志见 `artifacts/home-disk-layout/app-test.log`。
