# 百万级空间分析验收

后续源码优化与独立对照见 [2026-10-02 构建空间与分页优化](verification-optimization-20261002.md)。后续测量未复现此页的历史慢样本，不改变本页的正式验收结论；R3 桌面包未被覆盖。

验收结论：本阶段实现与测试包已完成，百万及三百万容量和资源验证通过；三百万普通页延迟目标未通过。具体结果、失败样本及追加诊断均列于本页。

本轮实施 Windows 批量目录读取、分配空间统计、会话临时索引、独立只读查询及游标分页。设计、取舍和新接口见[实现说明](analysis-million-design.md)。版本保持 0.18.0，交付目录独立于既有测试包。

## 环境与测量口径

实机为 Windows 10 专业版 10.0.19045、Intel Core i5-10400、约 16 GiB 内存。本轮没有在 Windows 11 重跑。进程令牌未提升；真实桌面验收使用未开启 `e2e-fixture` 的普通 Release 程序。F、G 是同一块 WDC WD10EZEX SATA 磁盘的分区；系统盘为 NVMe。

10 万、50 万文件夹具位于 G 盘，百万、三百万夹具位于 F 盘。初次大规模测量将索引也放在机械硬盘，记录在 `formal-final`；之后将索引放到 D 盘 NVMe 的专用测试目录，扫描源不变。目录覆盖索引修复前的完整序列为 `formal-ssd`，最终 R3 序列为 `formal-r3`。旧版索引始终在内存中。D 盘测前约剩余 8.87 GB，足够保留 2 GiB 余量；实际应用默认索引位于系统 SSD，用户也可通过设置选位置。本轮没有改变用户的应用索引设置。

大夹具每个文件 7 字节，文件名含中文，每个叶目录 1,000 个文件。独立调用 Windows `FileStandardInfo` 对照的分配量为 8 字节，记录在 `allocation-oracle.json`；NTFS 驻留小文件不能按簇大小估算。汇总核对百万及三百万的逻辑大小分别为 7,000,000 / 21,000,000 字节，分配空间分别为 8,000,000 / 24,000,000 字节，未知数为零。它验证元数据和索引规模，不代表真实整盘大小分布、海量压缩文件或大量共享硬链接。

旧、新 Release 同机顺序交替各五次，双方使用 50 万条上限，避免“新版读取更多所以更慢”的口径差异。50 万负载含目录节点，预期只收录 499,499 个文件并为 `partial`，不能称为完整扫描 50 万文件。新版本另以 500 万条防御上限完整扫描百万和三百万文件，各三次。

本任务的编译、夹具生成和桌面测试均在正式计时前完成；不清空系统文件缓存。其他项目活动未被终止，各轮 `*-load.json` 记录开始时编译进程数和可用内存，不能保证整段运行无外部竞争。旧、新二进制哈希在测量前后复核，原始样本不覆盖。

新分页样本在旧接口查询后测量，保护路径检查和部分数据库页已经预热。查询耗时只含后端返回，不包含 WebView 绘制；不将其当作应用冷启动或首次查询时延。索引峰值为每 250 ms 采样加终值，可能漏掉瞬时峰值。内存为原生分析进程私有提交高水位，包含读取阶段，不包括 WebView2；900 MiB 是本轮验收阈值，不是对任意目录树的硬内存保证。

## 正式结果（R3）

完整原始序列及机器可读结论见 `artifacts/analysis-million/formal-r3/summary.json`。文件数量、逻辑大小、去重大小、分配空间、终态及二进制哈希核对通过。**功能和规模验证通过，查询性能验收未全通过：三百万普通页 19/42 个样本超过 250 ms。**

### 同机扫描对照

耗时单位为秒，表中为中位数（最小–最大），均含遍历、索引写入及最终排行建立。

| 负载 | 旧版 | R3 | 中位耗时减少 |
| --- | ---: | ---: | ---: |
| 10 万文件，各 5 次 | 11.999（11.924–80.119） | 7.033（6.730–7.278） | 41.4% |
| 50 万文件负载，各 5 次 | 59.249（58.972–138.243） | 38.478（37.454–43.083） | 35.1% |

两组均达到本轮“中位耗时至少减少 30%”的目标。10 万双方完整；50 万负载双方同为 500,000 条、499,499 个文件，终态为 `partial`。慢的首轮样本完整保留，不剔除、不作为冷盘保证。

原生进程峰值的取舍也需要说明：10 万负载旧版约 77.1 MiB，新版约 88.1 MiB，固定缓存使小规模峰值略高；50 万负载则从约 376.1 MiB 降至 119.8 MiB。峰值含各自的查询阶段，新版还包含新分页接口。

### 查询与取消

查询耗时单位为毫秒。每种规模包含 42 个普通页样本及 12 个名称搜索样本，搜索条件为夹具名称包含 `099`。P95 使用 nearest-rank；三轮/五轮扫描的 P95 等于该小样本最大值，不能据此推断真实用户分布。

| 负载 | 普通页中位数 / P95 / 最大 | 名称搜索 P95 / 最大 | 所有普通页 ≤250 ms |
| --- | ---: | ---: | --- |
| 100 万文件 | 10.097 / 18.910 / 19.230 | 60.047 / 60.047 | 通过 |
| 300 万文件 | 234.341 / 678.273 / 756.376 | 327.704 / 327.704 | **未通过** |

所有查询返回成功，名称搜索首屏在 2 秒内。三百万普通页不只是单个异常点，**P95 和最大值均未达标**；文件页、目录页、空类别查询都出现慢样本。最终序列的三百万查询较此前 R2 序列更慢，不能把目录覆盖索引修改宣称为已解决整体延迟。两序列不是受控 A/B，现有记录不足以区分系统竞争、连接并发和代码路径的贡献。

| 取消场景 | 从请求取消到返回 / 终态 |
| --- | ---: |
| 首批条目后取消扫描 | 6 ms |
| 建立排行索引时取消 | 5 ms |
| 扫描过程中取消当前查询 | 559 ms，查询中断后扫描仍在进行 |
| 完成后三百万无匹配查询取消 | 最大 354 ms |

本机这些样本的取消均在 1 秒内。已中断查询没有被冒充为“查询先完成、随后取消”；扫描中的独立取消还核对了 `scan_still_active=true`。正在阻塞的系统调用仍不能强制中断。

### 延迟诊断与当前结论

追加了仅基准启用的分段计时功能，覆盖查询入口、连接打开、PRAGMA、快照读取、SQL 取 ID、详情组装、计数派发和资源释放。第二轮将记录缓存在内存，全部结束后才输出，减少即时日志改变线程时序的影响。

两轮各 90 次常规查询，最大分别为 193.153 / 110.701 ms，均未复现正式序列的超时。这些是不同诊断构建上的探索，**不能并入正式样本，更不能推翻 R3 的未通过结论**。诊断中第一次查询约 0.55–0.59 秒主要花在详情组装阶段，此处包含保护路径的首次初始化，尚未进一步拆分；预热后的 SQL 取 ID 最大约 84 ms。第一轮观察到一次读连接释放与计数连接初始化同时约 95 ms，第二轮未重复出现；这仍不足以确认根因。

本阶段交付为独立测试包。后续重点是三百万查询的事件级时序诊断及可复现回归，再据证据决定是否调整连接生命周期。当前没有把未定位的延迟归咎于机械硬盘，也没有将查询目标改为较宽松阈值来宣称通过。

### 早期序列保留

- `formal`：50 万负载空的已识别文件类别查询约 571 ms，停止后修正分类索引选择；原样本及 `INTERRUPTED.txt` 保留。
- `formal-final`：扫描源和索引同在机械硬盘，三百万完成约 1,257 秒，首次页面约 6.29 秒、一次目录用途页约 14.69 秒，普通页目标未通过。同盘还有其他项目编译和磁盘队列积压，不能分离归因。序列在首个 50 万基线中停止，不混入最终统计。
- `formal-ssd`（R2）：完整五轮对照及百万/三百万各三轮；扫描耗时减少 44.5% / 34.9%，但百万普通页最大约 1,073 ms、三百万约 900 ms，未全通过。R3 补齐目录覆盖索引，实际查询计划确认筛选及排序只扫描目录索引，随后重新完成正式序列；索引结构改进不等于整体时延已经达标。
