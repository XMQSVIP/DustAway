## 两种状态分别理解

“仅只读扫描”描述本版本规则能力；“运行中”“版本不支持”“身份未确认”描述本机条件。二者可以同时出现。关闭应用不会使只读规则开放；应用级旧字段 `cleanup_validated` 不能代替逐规则能力。读取失败、旧接口缺少 `rules` 或返回冲突条目时，界面保守显示能力未确认，不影响其他已有可清理项目。

## 本地只读证据

在项目根目录执行（输出目录必须尚不存在，其父目录须存在）：

```powershell
node scripts/application-evidence.mjs collect artifacts/applications-0.14/local-evidence
node scripts/application-evidence.mjs check artifacts/applications-0.14/local-evidence
node --test scripts/application-evidence.test.mjs
```

`collect` 调用现有 Rust 只读扫描示例，不启动或退出应用，不提交清理计划。扫描范围为内置六条规则、不叠加用户排除设置，因此候选量可能与界面选择不同。证据仅在本地生成，包含 `evidence.json` 和带附件大小、SHA-256 的 `manifest.json`；无个人路径、文件名、账号、自由文本错误或网络上传。应用信息示例也只输出脱敏字段；UI 原有扫描位置展示不受影响。

`check` 检查逐字段白名单、六条规则完整性、固定版本和保留期限、覆盖状态、附件哈希。实际安装版本不同会单列 `version_mismatches`；不能伪称支持。结构不完整或哈希错误以非零退出。材料完整仅表示证据可读；扫描失败由 `inspection_status=failed` 表示，真实删除验收仍为 `acceptance_status=not_run`。全部成功读取或零候选也不能通过删除验收，`may_enable_cleanup` 恒为 false。

验收记录状态区分：未执行、只读检查、真实执行失败、验收通过。本轮工具只产生前两类及只读扫描失败；不接收伪造的 `passed` 状态，不以 JSON 文件替代实测审阅。

## 未来隔离验收操作单

每条规则独立建立证据，使用隔离 Windows 与测试账号，不复制日常账号资料。记录系统版本、程序来源/哈希、准确版本、签名、标准布局、测试步骤、候选清单及采样时间。仅对合成保护资料做内容哈希与修改时间核对；证据附件去除账号与路径身份信息。

1. QQ 三类缓存分别由真实应用操作产生：关闭全部相关组件，核对计划后处理，重新打开应用并访问测试内容，验证目标缓存可再生成；测试登录、Local Storage、Session Storage 等持久数据保持。
2. 微信日志与 WPS 日志：使用满足期限的诊断样本，核对处理后可正常启动并产生新日志。验证近期文件、配置、合成聊天/文档资料与备份保持。人为回填年龄的样本必须标注，不能声称是自然生成的旧日志。
3. 微信转储：单独核对至少三十天的 .dmp 与不足期限样本，处理后启动及日志功能正常；不为生成转储而使日常应用崩溃。
4. 每条规则分别测试应用运行、扫描后重启、版本变化、路径替换、候选变化、进程状态未知、链接/云文件及排除项，确认拒绝或保留；比较保护文件内容与时间。
5. 记录每次计划与最终报告，逐项对应真实文件结果。空候选不能覆盖有效删除与再生成任务；缺证据、失败或保护数据变化不能通过。

所有对应证据齐备并审阅后，才能按规则修改后端静态 `validated`，再运行全量回归。当前工具和发行版没有 UI、环境变量或动态文件解锁入口。本轮没有可用隔离验收环境，六条规则保持未执行，不启用沙箱或安装应用。
