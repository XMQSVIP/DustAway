# CPU 用途模型 v3：真实元数据观察（2026-10-29）

本轮从人工合成样本推进到本机真实目录观察，并根据发现的深层日志结构优化特征。当前模型 `purpose-nb-v3-30c6dc541589`，14,338 字节、86 项词特征，仍只使用 CPU。桌面源码已使用该模型；没有重新打包桌面发行程序，没有扩大清理规则或删除权限。

## 实际观察范围

明确选择六个应用的缓存、代码缓存、图形缓存、日志和持久存储子目录，共 36 个根。使用生产 WindowsAnalysis 的只读遍历；仅取路径、文件/目录类型、大小和修改时间，没有读取正文、修改文件或执行删除。每根最多 300 条记录、3,000 次检查，事件回调检查 15 秒时间预算；不宣称可以中断阻塞的系统调用。

获得 1,012 条真实元数据记录，包含目录行：

- 开发分区：四个应用，共 581 条。
- 留出分区：另两个应用，共 431 条，未分析其模型结果、未用于选参数。
- 两个日志根触及 300 条记录上限，其余 34 根完成；未记录访问问题。按目录顺序采样，不是均匀随机样本，不表示覆盖整盘。
- 样本来自一台机器，应用共享 Electron/编辑器生态，不足以证明跨机器、跨软件生态的泛化能力。

首次 v2 冻结采样曾在单独的私有预测文件中保存所有条目的输出；优化过程中仅分析开发分区。当前采样器已改为完全不推理 holdout，v3 重打分文件中 holdout 明确标记 `withheld`。留出分区还没有经过独立逐文件标注，因此本轮不报告留出准确率。

原始文件位于本机 `artifacts/file-purpose-real-20261029/`，不加入源码数据集：

- `manifest.private.json`：明确采样范围。
- `observed/observations.private.json`：冻结的原始元数据及待复核状态。
- `observed/predictions.private.json`：v2 冻结输出。
- `observed/collection.json`：范围、上限、读取问题与完成状态。
- `development-report.json`：v2 的无原始路径汇总。
- `v3/development-report.json`：v3 在同一快照上的汇总。
- `review.private.json`：96 条盲标样本，全部待复核；不含模型答案，未生成训练标签。

这些私有文件含本地路径。`.gitignore` 排除 `artifacts/` 和 `*.private.json`，不上传用户样本。

## 根据观察作出的改动

实际日志经常位于 `logs/日期/window1/exthost/output/文件.log`。v2 最近两层目录要求导致不少具有 `.log` 类型且位于日志范围的条目拒绝判断。

v3 只对 `.log` 及已经支持的数字轮转日志扩大到最多六层目录特征，并且只有模型结论为 `logs` 时允许采用这六层的上下文。普通缓存、其他文件类型、目录自身分类仍保持原来的近层要求。所有资料目录冲突、敏感位置、保护扩展名和异常路径检查保留。新增测试覆盖深层日志、超出六层、文档/数据库/配置混入和未知缓存子目录。

训练仍使用原 225 条合成样本。v2 与 v3 的词权重完全相同，真实观察没有当作标签进入训练；重新生成模型是为了绑定新的特征版本和模型 ID。

## 同一快照的观察结果

| 开发分区指标 | v2 | v3 |
| --- | ---: | ---: |
| 观察条目（文件＋目录） | 581 | 581 |
| 给出用途推测 | 135 | 345 |
| 推测覆盖率 | 23.2% | 59.4% |
| 日志范围内文件给出日志推测 | 99 | 309 |
| 与目录范围参考冲突的推测 | 0 | 0 |

新增的 210 条推测均来自日志文件，缓存及持久存储样本的预测保持不变。**目录范围参考不是逐文件真值，所以上表不表示准确率提高或零误判。** 报告的 `accuracy` 明确为 `null`，未复核样本不会被计作正确分类或正确拒绝。

原有 122 条合成开发回归保持：69 条正确分类、49 条未知/保护项正确拒绝、另 4 条证据不足。九折训练软件组留出指标保持 173/225 条有正确预测、52 条拒绝。这些仍是参与开发的合成指标。
