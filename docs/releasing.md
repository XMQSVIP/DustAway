# 0.25.0 小范围测试版发行

本轮同时构建安装版与免安装版，均为未签名候选包。当前结果见[验收记录](verification-025.md)；没有人工与实机证据时不能称为稳定性验收通过。

## 构建顺序

1. 保存源码基线，完成规则投影和依赖声明；运行 `pnpm check:quality`。
2. 以 `node scripts/release-manifest.mjs snapshot <新文件路径>` 冻结源码清单。后续变更源码必须重新快照及构建。
3. 运行 `pnpm portable`，归档本轮免安装目录；随后运行 `pnpm bundle:installer`。两种构建使用相同源码，分别保留载荷与特性信息。
4. 使用构建清单工具为各包建立清单，校验源码未漂移、包文件哈希和声明的签名状态。清单绑定最终包；安装载荷的哈希另外从实际安装结果核对。
5. 在已确认的 Windows 10/11 专用环境核验启动、设置与历史沿用、旧版升级和权限边界。记录未执行项。

免安装构建不含 helper、不启用 system-cleanup；安装版启用现有受限系统维护。两种发行构建都不能包含 e2e-fixture 或测试许可。

## 证据与交付

独立目录保存源码清单、构建清单、安装包、免安装 ZIP、逐文件 SHA-256、验收结果和限制说明。原始测试日志、失败结果及历史包不覆盖；候选包只用于本轮验证。

构建清单 schema 1 仅用于追溯，不是删除许可。`snapshot` 保存当前受 Git 管理及非忽略源码的字节指纹；`create` 校验当前源码与快照一致，并要求显式选择 portable 或 installer。`check` 校验清单结构、包范围和每个文件哈希。

清单同时记录既有应用证据目录标识 `catalog_id` 和完整 Rust 规则投影的 SHA-256 标识 `rule_catalog_id`，不把应用子目录的标识当作全部规则的指纹。

正式签名与公开发行不在本轮；未来签名后必须重新生成最终载荷哈希，不能把哈希当作签名。
