# 拂尘用户手册

支持软件卸载和残留检查；已核验安装身份与布局的 Firefox 可选择清理八个固定残留范围，其他未验收范围保留。[使用方法与支持范围](software-uninstall.md)。

适用范围：0.24.0，Windows x64。旧版本以随包说明为准。当前支持数量由[编译规则摘要](current-capabilities.json)计算；具体项目仍需核验本机安装身份、布局、文件格式及运行状态。

0.24.0 新增 CodeBuddy 扩展日志、WorkBuddy 扩展日志、ToDesk 日志/网页缓存、钉钉日志与运行记录、WebToApi 网页缓存/日志、DBX 网页缓存，共八项只读识别。仅统计固定目录，全部保留，不增加可清理容量。 WebToApi 的备份、附件、生成图片、扩展和账号资料不在缓存范围；安装登记仅提供来源线索。详见 [本轮范围与验收](verification-coverage-024.md)。

0.23.1 分别显示扫描是否完成与是否允许清理。失败、中断和未完成的检查在首页常显；扫描中容量尚未确定时不会显示完整零值。折叠分类显示已保留容量和主要原因。查看、翻页、重试本页不改变选择；运行状态复查不发现新文件，重新扫描沿用原有选择确认流程。清理后“扫描时占用”不是仍保留空间。详见 [验收与限制](verification-clarity-0231.md)。

0.23.0 新增五项日志（Codex、Trae、Trae CN、Kiro、WorkBuddy）和五项网页缓存（豆包、UU 远程、CC Switch、ima、EasySpider）识别。仅统计固定目录，全部保留、不可选择；详情中的资料说明不代表已通过清理恢复验证。实际范围及限制见 [0.23.0 验收](verification-coverage-023.md)。

0.22.0 新增影刀、Codex、Claude、Docker Desktop 与 Reqable 的固定缓存/日志识别，全部只读。新增占用计入已扫描和已保留，不计入可清理；安装登记不代表已核验身份。空间分析中的资源、依赖和备份用途仅供判断，不会自动选择文件。详见 [0.22.0 验收](verification-coverage-022.md)。

## 完成一次清理

1. 首页默认只选择 **C 盘**。可勾选其他磁盘进行单盘或多盘扫描，也可选择“全部磁盘”。点击“开始扫描”，检查所选磁盘中的已支持垃圾位置；不会删除文件，也不会自动启动整盘空间分析。
2. 扫描结束后，已验证的建议项会自动选中。直接点击“清理已选”；结果页直接显示按用途分组的建议项，可取消整个分类；展开分类后点击“查看文件”，取消个别文件。
3. 核对文件数和大小，确认一次“永久删除”。文件不进入回收站，不能撤销。

若发现可清理内容但没有勾选，页面会提示“发现可清理内容，请选择”。“可自行选择”默认折叠，标题显示可选容量；用途分组分别显示可选量和已选量，尚未验收的只读内容不计入可选量。获准清理的项目被应用占用时，可保存工作、正常退出应用后点击“退出后重新检查”，候选和原有选择会保留，不会自动清理或强制结束软件。

运行中的应用可能导致暂时读不到候选文件；页面仍会列出受影响的检查项并提供退出后复查。钉钉网页与代码缓存已获逐项清理许可，两项均默认不选，须正常退出钉钉及后台组件。百度网盘三项继续只读，复查不能解锁。版本号用于验收记录和安装身份，不作为版本白名单；软件更新后须重新扫描。

窄窗口的结果页也可从扫描范围旁点击“重新全面扫描”，无需放大窗口。

完成后显示已删除文件大小与保留/失败数量，磁盘可用空间自动刷新。点击“完成”返回首页，记录仍保留在历史中，不会自动再次扫描；完成页不再展示底部任务栏和重新扫描按钮。详细原因从“查看清理记录”进入。状态不确定时明确显示未确认结果，可查看记录或返回首页，不会自动重试删除。无需去原应用处理后再回来完成任务。只读及受保护的占用不会计入建议清理量。没有可清理内容时可直接返回首页，磁盘选择保持不变。

清理页仅展示实际发现的内容，不再罗列零候选软件，也不提供完整规则目录入口。软件已卸载但仍有符合现有规则的残留缓存时，照常展示并按原有许可选择；软件是否安装不作为隐藏残留文件的条件。读取失败、应用占用和运行状态未知单独提示。磁盘选择保留。软件升级后的能力限制不会因点击退出重查或手动选择而解除。

至少选择一个可用磁盘才能开始扫描；C 盘不可用时需要自行选择其他磁盘，不会自动改成全扫。结果页显示本次扫描磁盘，“调整下次扫描磁盘”只影响下一次扫描，不会改写当前结果。磁盘选择与空间分析位置分开；选择全部磁盘也不将普通个人文件自动判定为垃圾。首页单盘显示该盘可用空间，多盘逐盘显示，超过三盘可展开其余读数。选择变化、手动刷新和清理完成会更新读数，没有后台轮询；查询失败时旧值标为上次读数。

## 开发工具缓存与 uv

扫描后在“开发工具缓存”分组查看实际发现的文件，各项默认不勾选。逐文件清理、官方工具整理与只读项目分别显示，当前能力以程序核验结果及[编译规则摘要](current-capabilities.json)为准。未发现文件的工具隐藏，卸载后留下的缓存仍显示。[工具清单与位置](developer-cache-coverage.md)。

uv 单独由官方工具整理：展开“已保留 → 开发工具缓存”，点击“整理 uv 闲置缓存”，核对位置与影响后确认。会清除工具判断闲置的缓存；缓存中的集中式项目环境也可能被移除并按需重建。普通项目 .venv、解释器和已安装工具保留。运行中的 uv / Python 或无法确认的缓存位置会阻止启动。

uv 的发现量不计入普通“清理已选”。完成后请重新扫描；回执分别显示缓存逻辑大小和磁盘变化，差值不代表实际释放空间。停止或中断后不会自动续跑；历史中的 uv 记录可手动清空。

## 保留指定文件

展开用途分类，点击具体清理项右侧“查看文件”，侧边文件页提供搜索、排序和分页（每页最多200项，并虚拟渲染）。取消文件勾选后立即显示“已保留，本次不清理”，总量同步更新；只选择一个需确认文件不会选中同类其他文件。

关闭侧页或按 Esc 返回原入口和滚动位置；同一会话重新打开该规则时保留搜索、排序、页码和明细滚动位置。切页、切换应用导航、重新核对应用状态不会恢复已取消的选择。分类复选框仅影响所在区域中的可执行项目，不改变其他类别或自选内容。重新扫描会重置该来源的选择。恢复旧任务仅恢复结果，不恢复删除授权。

“文件操作”中可在资源管理器定位，或加入长期排除草稿。批量保留入口收在“长期保留设置”；已有草稿时，即使设置折叠也会显示未保存数量与保存入口。草稿需要核对并保存；保存排除后旧扫描或计划失效，需要重新扫描。文件夹排除包含其子目录。

## 扫描及异常状态

扫描时显示当前用途及具体检查项（如“应用缓存 · 钉钉网页缓存”）、真实已检查数量和耗时，不显示估算百分比。已完成类别可查看明细，全部扫描结束前不能清理。停止请求与已停止分别显示。请求响应不确定时先核对受理状态，不重复执行删除。

部分位置未读取时会明确提示；无候选不等于整台电脑没有垃圾。浏览器占用影响其对应项目，其他可清理项目可以先处理。拂尘不会强制结束程序。

完成页展开“查看清理记录”，可查看保留、失败、不确定、未处理及未纳入计划的内容。旧报告或失效会话只保留统计，不伪造文件明细或恢复能力。

## 查找其他大占用

“空间分析”默认选择系统盘，也可以选择其他支持的本地固定 NTFS 卷或目录。主动点击“开始只读分析”。分析不读取文件正文，也不自动选择大文件。只有你主动选择、后端核验并确认的内容才会删除。

分析完成或停止后默认展示本次已读全范围的大文件，按大小降序。可切换“大目录”或“目录浏览”；用途是辅助筛选，不影响文件是否可以删除。“筛选”集中提供用途、最小大小、包含内部目录等条件；关闭筛选不会清除条件，已应用数量和清除入口仍然可见。清除筛选不会清除名称搜索。搜索与排序由完整索引查询，不是只处理当前200项。

排名条带只比较当前展示项。父子目录、硬链接的大小不能相加成可释放量。点击文件名查看详情，点击目录名进入目录，目录旁的“详情”可查看用途依据和完整路径。用途未知和受保护原因直接显示；系统设置、定位和长期保留等低频入口收在详情的“更多操作”。进入目录后“返回空间排行”恢复原筛选、页码、滚动和焦点。

统计不完整、正在建立索引、旧结果、查询失败各有提示。更换准备分析的位置不自动覆盖旧结果；清理后的旧分析会标记为清理前统计。分析最多读取 500 万条、128 层；达到数量、深度或资源限制时保留已提交的部分结果。

“统计口径”默认显示占用空间，也可切换为文件大小。占用按系统返回的分配空间计算，压缩和稀疏文件另行查询；未知值明确标出。目录内部按文件身份去重，跨目录硬链接仍可能共享数据。结果不含文件系统元数据、快照等，不能视为可释放量。显示“清理前核验”的项目还须重新检查身份、变更和硬链接数量。

为支持百万级目录，分析会在本地建立临时元数据索引，包含名称、路径及大小，不保存文件正文，也不写入清理历史或诊断导出。关闭程序或更换会话后清除；异常退出的本程序索引在下次启动回收，不恢复清理授权。设置中可更换索引位置；单会话数据库及 WAL 合计限额 4 GiB，所在磁盘保留至少 2 GiB 可用空间。索引自身不进入分析结果。列表每页 200 项先显示，总数在后台统计；扫描仍在更新时可能需要返回第一页刷新。

大量条目时，优先选择现有、空间充足的 SSD 存放临时索引。本机测试中，扫描数据和索引共用繁忙的机械硬盘出现过明显慢查询；换用 SSD 索引后改善，具体配置和限制见[本轮验收](verification-analysis-million.md)。

## 自选文件和文件夹

在空间分析结果或“文件详情”中勾选不再需要的普通文件或文件夹，勾选即加入本次清理，取消勾选就是本次保留。直接点击底部“清理已选”，在原页核验并确认一次永久删除，确认后进入清理任务页。无需先返回清理页，也不必先扫描垃圾。“查看已选”是可选入口，用于查看清单，不改变选择。如果垃圾扫描中也有已选内容，底部会明确提示，确认框分别列出垃圾扫描项目和自选范围。

清理页和分析页共用扫描记录中的已选大小、文件数与文件夹数，各页只保留一份主要汇总。连续勾选时显示“正在统计”；统计失败保留选择，仍可进入最终核验。空文件夹也可清理。真正删除前重新核验，以确认框中的冻结清单为准。取消确认、停止准备或核验失败后，保留原页的选择、搜索、页码和滚动位置，并恢复清理入口焦点。核验为空时留在原页说明，不出现空确认框。选择变化后需要重新准备计划。

建议清理直接展示；“可自行选择”和“已保留”默认折叠。已有自选内容时，展开“自选文件与文件夹”查看清单。自选范围合并已包含的后代，支持按名称或路径搜索、分页（每页最多200项）、逐项移除、查看目录内容和取消全部自选。取消整个文件夹会取消其后代，取消子项则保留其他选择。

选择文件夹表示选择本次已读取的内容。可进入文件夹取消子项，也可重新选择被取消子目录中的个别文件；半选表示只选择了部分内容。搜索、翻页、排序和关闭详情不会丢失选择。详情仅用于查看和勾选，不包含持续核对任务；关闭或按 Esc 返回原搜索、页码、滚动位置和入口。父子重叠不重复计算。选择本页只处理当前页可删除项目。

统计不完整的文件夹不能整批选择，可逐文件选择已读取的完整结果。“长期保留”把此项加入排除设置。更改排除后需重新分析。垃圾重新扫描仅清除垃圾来源选择；空间重新分析仅清除自选来源选择。新分析会关闭旧会话详情。

确认框列出自选范围的名称、路径，以及核验后的文件和文件夹数量。只清理清单内的文件，确认后新增的内容会保留；文件夹最终不为空时会保留。停止不会恢复已删除内容，重启不会自动继续删除。

系统位置、已识别的安装和应用核心数据、拂尘数据、链接、云文件、多硬链接和占用文件会保留。用户主目录等容器本身不能删除。内置清理规则覆盖的位置只能通过对应规则选择，不能用自选入口绕过条件或验收限制。只读应用缓存仍然只读。

## 历史与设置

历史按日期呈现清理回执，首先显示时间、结果状态和实际删除量。展开核对各类别及磁盘变化。本地保留30天；清空历史单独确认，不删除用户文件。

设置分为“外观”“保留清单”“帮助与关于”。外观支持跟随系统、浅色、深色和减少动效；减少动效也遵循系统设置。保留清单集中管理文件、目录和高级类别排除；保存失败会显示错误，不能按已保存处理。帮助中提供 Windows 存储入口、诊断导出、版本与能力范围。

## 能力范围与运行方式

0.21.0 的微信区域分别显示扫描、清理能力和运行状态。“重新检查微信运行状态”保留原候选和选择，不发现新文件；更新占用须重新常规扫描。附件分类显示扫描时占用，本次已删除量与保留/待核验量分别列出，重新扫描会清除选择。当前规则数量见 [编译摘要](current-capabilities.json)，测试与限制见 [0.21 验收](verification-weixin-021.md)。

0.21.1 完善仅通过 SSH 的非交互测试和证据校验，真实微信缓存仍只读。网页恢复和桌面视觉未验收，不因此开放代码或图形缓存清理；详见 [0.21.1 验收](verification-weixin-0211.md)。

0.20.0 提供 115 条普通用户扫描规则；按条件清理、官方工具操作和只读识别分别展示，发现占用不代表已经允许删除。安装版另提供主动授权系统扫描，范围见 [系统清理](system-cleanup-acceptance.md)。应用版本记录作验收背景，实际操作按 [安装身份、布局与格式](cleanup-compatibility.md) 核验。

清理页的“微信专项清理”显示缓存与日志的占用及保留原因。选择“整理微信聊天附件”，选定一个账号后主动扫描，可按图片、视频、语音、接收文件和未知格式查看占用。默认只列出最后修改超过 30 天的附件；分类仍统计近期文件，点击“查看全部时间”可查看它们。附件默认不选，选中后独立确认永久删除。

微信当前支持标准 4.x 布局和经过核验的自定义账号目录；加密 DAT、未知格式、聊天数据库、收藏、备份和登录信息保留。网页代码与图形缓存尚待完整网页恢复与重建验证，其他只读项目也不能通过退出微信解锁。具体范围见 [微信专项 0.21 验收](verification-weixin-021.md)。

应用升级后，身份与目录结构匹配仍可只读发现。界面的版本是观察信息，“已识别目录结构”不代表通过删除验收。飞书和钉钉只检查明确缓存子目录，不包括聊天附件、离线邮件、文档或登录资料；QQNT 不使用经典 QQ 规则。受保护项目保留，具体范围和保留原因收在详情中。

百度网盘只检查网页、代码与图形缓存；夸克和迅雷只检查代码与图形缓存，不代表整个软件占用。空间分析对配置根、持久存储和 .xltd 的说明是用途线索，不判断下载完成或云端副本。普通资料是否保留由你决定，保护边界仍由后端核验。

个人下载和文档不进入自动建议，只能主动自选。聊天核心资料、注册表、Windows更新组件和回收站保持保护。本轮“全面”仅指本版本支持的常见位置；全磁盘遍历由空间分析承担。普通用户版不自动提权，不加入后台扫描或遥测。

## 结果分组

结果采用临时文件、浏览器缓存、应用缓存、系统图形缓存、日志与错误报告五种用途，空分类不展示。浏览器和应用内的图形缓存仍归入各自缓存，DirectX 单列为系统图形缓存。分类仅用于展示，不代表整类都获准删除。

建议项默认选择；可自行选择项默认不选。两处的分类复选框各自独立，半选表示部分候选已选择。清理项显示已选大小和可选总量；已保留内容只显示发现量，不进入已选汇总。部分检查未完成时单独提示，不把无法读取当作没有垃圾。

核验后没有可删除内容时不会出现可执行的空确认框；核验缩减了范围时，在同一确认框说明。确认框中的数量和大小以冻结清单为准。

## 等待统计、准备与结果提示

勾选后的大小是扫描记录中的估计。正在统计时仍可调整选择，也可直接点击“清理已选”进入最终核验；超过两秒显示已用时间。统计失败会保留选择并提供重试，不显示虚假的零值。取消确认后，同一有效选择已完成的统计会保留。

准备清单时可以点击“停止准备”。页面显示“正在停止准备”，等待当前检查返回后恢复操作；选择保留，没有执行删除，也不会展示部分清单。取消清理仅停止后续删除，已删除内容不能恢复。

文件和文件夹分别记录处理结果。只有空目录成功删除也可以显示“清理完成”；还有目录未处理、失败、停止或异常保留时显示“清理已结束”。结果不确定或报告数量矛盾时显示“部分结果尚未确认”，可以查看原记录或返回首页。无法解释的数字显示“统计不可用”；不会自动再次删除。

## 软件卸载

进入“软件卸载”可按名称或发布者搜索，筛选桌面软件、商店应用，并按名称、大小或安装日期排序。打开详情核对版本和卸载影响后确认；桌面软件可能继续展示自带向导。商店应用标准卸载可能同时删除应用数据，不能保证留到残留检查时再选择。登记大小是估计值，不计入实际释放空间。

操作流程是：选软件 → 卸载 → 自动检查残留 → 选择清理或暂不清理。详情中的“卸载此软件”直接可见，安装位置和清理范围需要时再展开。

完成向导后，拂尘自动检查卸载结果和支持范围内的残留。全部默认未选，可用“选择本页缓存”批量选择当前页可清理的缓存；设置和资料需要单独选择。点击“清理已选残留”后确认具体清单才会永久删除。“暂不清理”直接返回列表；同一会话可用“查看处理结果”重新打开，不会再次卸载。

结果无法确认时，等向导结束后点击“检查卸载结果”；需要重启时先保存工作并自行重启。切换页面仍能查看任务状态。关闭拂尘仅停止跟踪，不强制结束卸载器；再次打开只核对原任务，不重新卸载或继续删除。已结束的旧任务收起为简短结果入口。

若残留处理被停止，结果中的“未处理”表示已确认选择中尚未开始的项目，这些项目不计入释放空间；“待核对”表示处理结果尚未确认。已删除内容不会恢复。即使任务显示待核对，已保存的处理数量仍可在页面和历史中查看。

本次卸载确认完成后会自动检查残留。目前已核验安装身份与布局的 Firefox 支持八个范围：缓存、两份设置、Cookie、历史、站点存储、书签备份和会话备份，实际可选项以后台核验结果为准。全部默认不选；选择资料可能清除登录状态、浏览记录、书签或标签页的恢复副本及离线内容，须再次确认才会永久删除。未通过安装身份、布局核验及尚未验收的软件规则继续保留。“部分位置未能检查”与“没有发现残留”分别显示。重新扫描会清除旧选择和确认。重开程序后原残留范围失效，展开结果时会说明不能继续检查或清理，历史摘要仍可查看。

商店应用可能与其他包共享数据。存在共享关系或系统不能完整核验时，拂尘会保留数据并说明原因；没有发现应用安装登记，不等于这些数据可清理。这不影响该应用按 Windows 策略进行标准卸载。

商店应用中名称为 LocalCache 的目录也可能保存设置、个人资料或离线内容，拂尘将它归入“设置与本地资料”。目录名含有 Cache 不表示其中内容可以重新下载或恢复。

商店应用或后台组件仍在运行时，残留会保留；无法确认进程状态也会单独说明。拂尘不强制关闭应用，可以退出相关程序后重新检查。停止检查会等待正在进行的系统查询返回，再停止后续处理。

检查包含大量文件的目录时，也可随时请求停止，无需等待整个目录列完。达到十万条遍历上限或部分文件无法读取时，结果会明确标为不完整，不能视为没有残留。

残留规则的逐项范围和验收状态见[软件卸载说明](software-uninstall.md)。软件卸载与普通扫描、清理、空间分析按顺序执行，避免同时处理同一内容。

## 官方工具整理与空间复核

uv 在独立的“官方工具整理”区域操作，不计入逐文件清理的已选容量。整理完成或结果不确定后，旧 uv 扫描容量失效，其他清理项的选择保留。再次整理需重新扫描；完整重扫沿用原有选择重置规则。未发现闲置缓存时明确显示零收益，不把执行成功当作释放空间。

完成页直接展示报告记录的逐盘清理前后读数，以及最新可用空间。缺失采样显示“未取得”。文件逻辑删除量与可用空间变化分别展示，不能相加或互相替代。可继续查看结果、重新扫描或查看大占用。
